## 1. 小程序真机联调验收清单（决策第 1 项）

前置（待用户）：正式小程序账号（管理员、所属主体、拟用服务域名）；appid+AppSecret 经受控部署渠道注入，不写进仓库。

**A. 登录换取微信身份（独立验收，不与 B 混合记账）**

| # | 步骤 | 预期 |
| --- | --- | --- |
| A1 | 真机打开小程序，发起微信登录 | 换取 openid 成功，进入业务页 |
| A2 | 构造登录失败（如临时改错密钥后再恢复） | 有明确失败提示，不白屏、不静默 |
| A3 | 核对服务端日志/会话 | openid-session 兑换链路落库正确 |

**B. 顾客自助绑定与查询（用内部测试档案）**

| # | 步骤 | 预期 |
| --- | --- | --- |
| B1 | 测试档案自助绑定 | 绑定成功，指向正确顾客 |
| B2 | 同一档案重复绑定 | 被拒绝或幂等，不错绑 |
| B3 | 两个不同微信身份绑同一档案 | 冲突被拒绝，可理解提示 |
| B4 | 绑定后查卡 / 查约 | 只返回该顾客自己的数据 |
| B5 | openid-bind 自助绑定入口 | 与 B1–B4 同口径 |

**短信独立上线门槛**：短信送达方案、费用负责人、接入范围三项明确并接入真实网关前，本联调只能记「内部联调」，不得记「顾客全流程可用」。当前验证码只落库+日志（`KioskController` sms-code、`WxOfficialAccountService` 绑定取码复用同一桩），真机联调时以日志取码核对流程，不作为顾客正式使用方式。

## 2. 公众号分段联调检查表（决策第 2 项）

**前置配置（逐项分开，缺一项只定位该项）**

| # | 配置 | 说明 |
| --- | --- | --- |
| P1 | 公众号账号信息（待用户） | 类型（服务号/订阅号）、认证状态、实际可用接口、正式域名、管理员；与小程序账号分别登记，两套 appid/AppSecret 不混用 |
| P2 | `WX_OA_CREDENTIAL_KEY` | 部署环境注入；**须有可恢复的保管方式**（否则换机读不回 `wx_accounts` 已存密钥） |
| P3 | 回调 token / `WX_OA_ENABLED` | 部署环境注入 |
| P4 | `WX_OA_OAUTH_REDIRECT_BASE` + 账号后台「网页授权域名」 | 两者必须指向同一域名并已在公众号后台登记 |
| P5 | 加密消息 AES key（可选） | 需要安全模式时经 ADMIN 入口配置 |

**验证顺序（每项记成功/失败与证据，失败不阻塞下一项排查记录）**

| # | 阶段 | 预期 |
| --- | --- | --- |
| V1 | 回调接收与回复 | 关注/发消息，服务端落流水并按规则回复 |
| V2 | 菜单推送并在手机看到 | `pushMenus` 出网成功，手机端菜单生效 |
| V3 | 网页授权正确回跳 | H5 绑定页经 OAuth code→openid 后回跳与 state 验签通过 |

账号能力不足时仅验证实际支持的部分并如实记录。
