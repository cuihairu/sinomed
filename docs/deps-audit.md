# Dependabot alert cleanup (staged upgrade rounds)

Baseline: GitHub dependabot open alerts **188** (snapshot 2026-10-08: critical 29 / high 74 / medium 74 / low 11).
Distribution: npm 187 (`app/pnpm-lock.yaml` 131, `web/pnpm-lock.yaml` 52, `docs/pnpm-lock.yaml` 4) + rust 1 (`desktop/src-tauri/Cargo.lock`, glib).

Agreed policy:

- Every alert lands on a **transitive dependency in a lockfile** (all manifests are lockfiles, never a direct dependency declaration). Three fix tiers:
  1. **In-range upgrade**: `pnpm up --depth=Infinity --lockfile-only <pkg>@<fix>` changes the lockfile resolution without touching node_modules;
  2. **Pin via overrides**: when the fix version falls outside the parent dependency's semver range but the package is dev-only or on an unused path, force it through `pnpm.overrides` in package.json (backed by a full green build + test run);
  3. **Register as upstream-blocked**: no patched version exists (NO-PATCH), or the fix version is pinned dead by the upstream dependency tree (e.g. Taro 3.6.x pins swiper 6) → register it honestly and leave it.
- **Each batch is committed and pushed only after a full green run**: server `./mvnw test` + builds for web/kiosk/tablet/app + desktop `cargo check`.
- Alert counts close automatically as upgrades land; the completion bar is the dependabot panel reaching zero (or remaining = blocked registrations).
