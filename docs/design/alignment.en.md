# UI prototype → gap list against current state and alignment plan

> 🌐 [中文](./alignment.md) · **This page is in English**

Reference baseline: [docs/design/mockups](./mockups/README.md) (tokens.css is the single style source for all five clients: the default "graphite × antique gold" theme is taken from the logo #666666/#C7A674, with three switchable primary colors via `data-theme="pine|cinnabar|indigo"`; rice-paper background `--paper`, gold-amber accent `--amber`, serif headings `--serif`).

Agreed conventions:

- **P0** = high-frequency core-path screens (patient records, treatment entry, global shell theme), aligned pixel-perfect first; **P1** = remaining implemented screens aligned one by one; **prototype only** = planned features, no implementation scheduled.
- Gaps are grouped into four categories: **layout / color scheme / components / copy**.
- The **data support** column marks whether each information block in the prototype has a real interface behind it: `✅` directly usable; `⚠️` requires frontend aggregation; `❌` no interface. Blocks marked `❌` are rendered as a "planned feature" placeholder or not rendered at all during implementation — **no fake data** (same warning convention as app.md).
- Each screen is committed independently once done (titles in the style `feat(web): patient record aligned to prototype`), with local dev server screenshots compared against the prototype images in `docs/public/screenshots/` before committing.
