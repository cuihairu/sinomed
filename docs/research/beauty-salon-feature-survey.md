## 一、客户与会员

### 1.1 会员等级

- **为什么需要**：美容院复购依赖长期关系，等级体系用权益（折扣、专属项目、赠礼）激励客户持续消费与升卡，是锁客的基础设施。
- **常见实现方式**：定义等级规则（按累计消费、储值金额或成长值），系统在交易后自动计算升降级；等级关联折扣率与专享权益，订单结算时按客户当前等级取折扣。
- **国内同类美业 SaaS 如何做**：常见做法是把会员分层与客户标签结合，例如美务通提供「ABCD 类客户划分」按价值分层维护 VIP（[美务通会员管理](https://meiwutong.com/hygl.htm)）；有文章描述以会员体系带动复购的运营路径（[知乎专栏](https://zhuanlan.zhihu.com/p/31856050370)，观点性文章，效果数据未核实）。
- **来源**：meiwutong.com/hygl.htm；zhuanlan.zhihu.com/p/31856050370。

### 1.2 储值卡

- **为什么需要**：储值（充值送）是美容院最主要的现金流与锁客手段；余额涉及预收资金，账目必须逐笔可追溯，否则易产生纠纷。
- **常见实现方式**：会员账户表 + 余额流水表联动；本金与赠送金额分字段记录（退款时只退本金）；每次变动生成流水与快照，用订单号等做幂等与对账（[CSDN：储值卡与次卡的数据模型与核销逻辑](https://blog.csdn.net/wencongta/article/details/163037065)）。
- **国内同类美业 SaaS 如何做**：主打「充值赠送规则灵活可配」（充值满赠多档位），并与提成联动（技师售卡即时计提）；行业文章普遍把「储值规则死板、漏扣错扣」列为常见痛点（[固乔科技测评](https://www.goodgq.com/h-nd/67968.html)，厂商测评性质）。
- **来源**：blog.csdn.net/wencongta/article/details/163037065；www.goodgq.com/h-nd/67968.html。

### 1.3 次卡 / 疗程卡

- **为什么需要**：美容院项目多为疗程式（如「10 次补水护理」），客人买卡后分多次到店，靠手工记录极易漏记、错扣，引发投诉。
- **常见实现方式**：卡项实例（购卡后生成，携带总次数/剩余次数/有效期），服务核销时扣减 1 次并生成核销流水；支持按项目或项目组限定适用范围。
- **国内同类美业 SaaS 如何做**：一键创建多档位次卡、收银时报手机号快速找到会员核销，剩余次数实时同步到会员微信端（[cnblogs 实测文](https://www.cnblogs.com/qtyj/p/19777074)、[新浪转测评](https://k.sina.cn/article_7857141524_1d4527714019046cnu.html)，厂商测评性质）。
- **来源**：zhuanlan 见 cnblogs.com/qtyj/p/19777074；k.sina.cn/article_7857141524_1d4527714019046cnu.html。

### 1.4 积分

- **为什么需要**：积分是低成本提高复购与到店频次的手段；美容院常以「消费得分、积分抵现/兑礼」维系低频客户。
- **常见实现方式**：订单完成后按折后金额折算积分入账；消耗支持积分抵扣现金或兑换商品/项目；积分流水独立记录、可冲正。
- **国内同类美业 SaaS 如何做**：营销型 SaaS 把「积分兑换」与优惠券、老带新并列为基础工具（[企叮咚](https://www.7dingdong.cn/t/%E8%80%81%E5%B8%A6%E6%96%B0%E8%A3%82%E5%8F%98)、[朗尊软件会员增长页](https://www.legendshop.cn/saas/member-growth.html)）。
- **来源**：www.7dingdong.cn（营销工具清单页）；www.legendshop.cn/saas/member-growth.html。

### 1.5 生日 / 回访提醒

- **为什么需要**：美容院客户决策周期长，生日营销与消费后回访（当天/3 天/7 天）是行业惯用的复购抓手；依赖员工记性必然遗漏。
- **常见实现方式**：会员档案记录生日；订单完成后按规则生成回访任务（谁该回访、上次消费了什么），配合定时任务在生日/回访节点推送提醒给店员或客户。
- **国内同类美业 SaaS 如何做**：美碧称「客人消费后系统自动标记回访提醒，员工在系统看到谁该回访、上次消费了什么」（[美碧回访系统横评](https://www.meiruhe.com/news_detail_news-ba7a7bf5-e1f1-4a3a-855a-41778657682b.html)，厂商内容）；美盈易提供「客户档案智能分层跟进，每一步有记录、有提醒」（[美盈易客户管理](https://www.dyysoft.net/bbgl.html)，厂商宣传）。
- **来源**：www.meiruhe.com/news_detail_news-ba7a7bf5-e1f1-4a3a-855a-41778657682b.html；www.dyysoft.net/bbgl.html。

### 1.6 客户标签与肤质 / 过敏记录

- **为什么需要**：美容服务直接作用于人体，过敏源、肤质、禁忌项目不记录清楚有服务事故风险；同时标签（来源渠道、偏好、消费力）支撑精准营销。
- **常见实现方式**：标签体系（自动标签：来源、消费层级；手工标签：肤质、偏好）+ 档案表单（过敏史、禁忌、健康备注）；服务/营销触达前提示过敏与禁忌信息。
- **国内同类美业 SaaS 如何做**：美务通以「会员标签 + 新客来源自动标记 + 手机端维护客情、邀约回访」为卖点（[美务通](https://meiwutong.com/hygl.htm)）；美盈易强调档案分层跟进（[美盈易](https://www.dyysoft.net/bbgl.html)）。肤质/过敏属健康相关字段时的合规要求见第八节。
- **来源**：meiwutong.com/hygl.htm；www.dyysoft.net/bbgl.html。

## 二、预约与排班

### 2.1 项目时长管理

- **为什么需要**：美容项目时长差异大（30–120 分钟），时长是预约占位与冲突检测的基本单位，没有时长就无法判断时段可用性。
- **常见实现方式**：项目定义中携带标准时长；预约时按「开始时间 + 时长」生成占用区间；系统按排班模板生成可用时段（slot），节假日单独调整（[阿里云开发者：时段锁与排队设计](https://developer.aliyun.com/article/1770104)）。
- **国内同类美业 SaaS 如何做**：预约流程中按项目时长锁定技师与房间资源；行文多与「智能调度」合并宣传（[RateMyPOS 美容院 POS 推荐](https://ratemypos.com/8280/)，第三方测评博客）。
- **来源**：developer.aliyun.com/article/1770104；ratemypos.com/8280/。

### 2.2 技师排班

- **为什么需要**：预约能否成立取决于技师当班情况；跨天班次、技师等级（指定高级技师）都影响可约时段。
- **常见实现方式**：周排班模板（工作日/周末班次）按日生成排班记录，支持临时调班；预约校验「技师在该时段当班且无其他占用」。
- **国内同类美业 SaaS 如何做**：技术文章描述美业排班需处理「技师等级、跨天班次、预约时段重叠」多重约束，用时间区间重叠检测保证一致性（[CSDN：美容院排班系统](https://blog.csdn.net/weixin_30444111/article/details/165910079)，技术实践文章）。
- **来源**：blog.csdn.net/weixin_30444111/article/details/165910079。

### 2.3 工位 / 房间占用

- **为什么需要**：美容院的护理房间/床位是稀缺资源，只锁技师不锁房间会出现「技师有空但房间被占」的现场混乱。
- **常见实现方式**：房间/工位作为资源实体参与预约；预约需同时通过「技师冲突」与「房间冲突」双重检测；房间可与项目类型绑定（如仪器项目专用房）。
- **国内同类美业 SaaS 如何做**：行业文章把「技师档期乱、房间用不上」列为核心痛点，系统按预设规则动态匹配技师与房间资源（[搜狐：美容院智能预约排班](https://www.sohu.com/a/940656543_120913056)，厂商软文性质）。
- **来源**：www.sohu.com/a/940656543_120913056。

### 2.4 预约冲突检测

- **为什么需要**：客户自助预约 + 前台手工预约并存，没有并发冲突控制就会超约、撞单，直接产生客诉与退单。
- **常见实现方式**：提交预约时即时检测技师/房间/会员三维度时间区间重叠；并发场景用条件更新（乐观锁/唯一约束）防止同时下单超卖，取消时对称释放资源（[阿里云开发者](https://developer.aliyun.com/article/1770104)）。
- **国内同类美业 SaaS 如何做**：美盈易称「客户提交预约请求时即时检查时间段和美容师资源的可用性，避免预约重叠」（[美盈易](https://www.dyysoft.net/hyzx/1752116455291826.html)，厂商宣传）；国际同类产品 Darkroom 亦提供逐层冲突排查（订单时间、员工安排、门店档期）（[Darkroom 帮助中心](https://www.darkroom.net/docs/calendar-and-staffing/resolve-booking-conflicts)）。
- **来源**：developer.aliyun.com/article/1770104；www.dyysoft.net/hyzx/1752116455291826.html；www.darkroom.net/docs/calendar-and-staffing/resolve-booking-conflicts。

### 2.5 改约与爽约管理

- **为什么需要**：客户改期、迟到、爽约是常态；技师时间被白白占用，旺季尤其严重，需要「低摩擦改约 + 有成本的爽约约束」。
- **常见实现方式**：预约状态机（待确认/已确认/已完成/已取消/爽约）规范流转；改约实现为改期操作保留原单；爽约约束常见两种：收取定金（爽约定金不退，依合同约定处理，见[律图法律问答](https://www.64365.com/zs/11914679.aspx)）与预约前自动提醒（到店前 1 天/2 小时推送）。
- **国内同类美业 SaaS 如何做**：大陆厂商多以「自动提醒降低爽约」为主；台湾市场报道美业爽约率约 10%–20%，并讨论预收定金的合规边界（[NEXT X Insights](https://www.nextx.com.tw/blog/taiwan-beauty-salon-no-show-prevention-2026)、[ezPretty](https://www.ezpretty.com.tw/blog/inner?id=133)，台湾数据与法规语境，未核实大陆情况）。
- **来源**：www.64365.com/zs/11914679.aspx；www.nextx.com.tw/blog/taiwan-beauty-salon-no-show-prevention-2026；www.ezpretty.com.tw。

## 三、项目与价目

### 3.1 服务项目库

- **为什么需要**：美容院项目数量多、更新快（季节项目、仪器项目），需要统一的类目/项目档案支撑预约、收银、提成、报表各环节。
- **常见实现方式**：类目（面部/身体/仪器/特护…）+ 项目（名称、时长、原价、适用部位/禁忌）两级结构；项目可上架到小程序供客户浏览与预约。
- **国内同类美业 SaaS 如何做**：项目库与预约、收银一体化是各家标配（美业 SaaS 通用能力，[七韵数店](https://www.qiyun.work/)等官网表述；具体某厂商细节未核实）。
- **来源**：www.qiyun.work。

### 3.2 套餐 / 卡项组合

- **为什么需要**：「项目 + 赠送 + 折扣」打包售卖是美业主流成交形态；套餐可能分多次核销，拆分记账复杂，必须系统化。
- **常见实现方式**：套餐主表 + 子项目明细（各子项目数量与单次价值）；售卖生成卡项实例，核销时按次扣减并把业绩拆分到子项目；与储值卡、次卡并称多类卡项。
- **国内同类美业 SaaS 如何做**：行业文章称头部系统「支持次卡、储值卡等四类卡项一键创建」（[cnblogs 实测文](https://www.cnblogs.com/qtyj/p/19777074)）；头条选型文强调「客人买了套餐分几次做，靠本子记迟早乱」（[今日头条选型文](https://www.toutiao.com/article/7695761075669369344/)，厂商软文性质）。
- **来源**：cnblogs.com/qtyj/p/19777074；www.toutiao.com/article/7695761075669369344/。

### 3.3 成本与定价

- **为什么需要**：美容项目毛利结构不透明（耗材 + 人力时长），没有成本基准就无法判断促销底线与主推优先级。
- **常见实现方式**：项目关联耗材清单与标准工时，成本 = Σ耗材成本 + 工时人力成本；售价参考目标毛利倒推；报表呈现项目维度毛利。行业内也有以「耗材使用量预测」控制成本的思路（[POS 评测博客](https://pos-us.com/1505/)，第三方博客）。
- **国内同类美业 SaaS 如何做**：公开资料中未见完整的「项目级成本定价」通用方案细节，多为进销存 + 报表间接支撑（未核实有厂商提供完整定价工具）。
- **来源**：pos-us.com/1505/。

### 3.4 耗材关联（项目 BOM）

- **为什么需要**：一次护理消耗精华、面膜、一次性用品若干，不做关联就无法按服务自动扣库存，成本与损耗都是糊涂账。
- **常见实现方式**：项目-耗材映射表（每项目每次消耗哪些耗材及用量）；服务核销时自动生成耗材出库；用量异常可人工调整。
- **国内同类美业 SaaS 如何做**：定制型厂商以「每次做项目自动扣减耗材，临期提醒、库存低提醒」为卖点（[优易云商](https://ueas.cn/soft/meirongyuan-jxc/)，厂商宣传）。
- **来源**：ueas.cn/soft/meirongyuan-jxc/。

## 四、收银与对账

### 4.1 消费结算（组合支付）

- **为什么需要**：美容院一笔消费常混合「储值余额 + 次卡 + 现金/扫码 + 积分抵扣」，手工记账无法保证账实一致。
- **常见实现方式**：订单 + 多行支付明细；卡项核销优先于现金类支付；结账即触发积分、提成、回访任务等下游事件。
- **国内同类美业 SaaS 如何做**：收银台「报手机号快速查会员、完成收银核销」是标配流程（[cnblogs](https://www.cnblogs.com/qtyj/p/19777074)）；行业文章强调收银单、预约单、业绩数据需打通（[搜狐实测文](https://www.sohu.com/a/1024659312_122717670)，厂商软文性质）。
- **来源**：cnblogs.com/qtyj/p/19777074；www.sohu.com/a/1024659312_122717670。

### 4.2 退单 / 冲正

- **为什么需要**：服务不满意退款、录单错误冲正天天发生；储值/次卡/积分都是预收资产，退款必须连动回退，否则账目不可信。
- **常见实现方式**：基于原单生成逆向单据（退款单/红冲单），不物理删除原单；同步回退余额、次数、积分与已计提提成（提成回退的具体处理各系统差异大，未核实）。
- **国内同类美业 SaaS 如何做**：技术文章普遍要求「会员主表与余额流水表联动、快照与对账日志保证每笔变动可追溯」（[CSDN](https://blog.csdn.net/wencongta/article/details/163037065)）。
- **来源**：blog.csdn.net/wencongta/article/details/163037065。

### 4.3 提成计算

- **为什么需要**：美容师薪资以提成为主（手工费、售卡奖、销品奖），规则多维且易争议；月底手工核算耗时且常引发纠纷。
- **常见实现方式**：提成规则引擎（项目 × 技师等级 × 岗位/角色的比例或阶梯），结账时自动生成个人提成记录，月底出工资单；支持多人分佣。
- **国内同类美业 SaaS 如何做**：傲蓝称系统自动整合「产品销售提成、按项目与技师等级的手工费、办卡奖励」（[傲蓝](https://www.aolan.net/meirong/a4612.html)，厂商宣传）；美盈易称支持按岗位、项目、时段、客户类型设置差异化提成（[美盈易](https://www.dyysoft.net/syjz02/1778396504342183.html)，厂商宣传）；多篇文章描述「手工/仪器/产品不同比例、月底对不上数」的典型场景（[优易云商](https://ueas.cn/soft/meirongyuan-ticheng/)）。
- **来源**：www.aolan.net/meirong/a4612.html；www.dyysoft.net/syjz02/1778396504342183.html；ueas.cn/soft/meirongyuan-ticheng/。

### 4.4 日结 / 月结与交接班

- **为什么需要**：前台多班次轮替，交接不清会出现长短款责任不清；老板需要日结/月结口径核对现金、扫码、储值消耗等各类收入。
- **常见实现方式**：班次交班单（本班各支付方式应收 vs 实收 + 差异说明）、日结报表（按支付方式/项目/员工汇总）、月度汇总与对账导出。
- **国内同类美业 SaaS 如何做**：有赞门店交班日结提供「交班/日结小票与收银端数据同步，缴款单与订单数自动匹配，一键对账、即时核查差异」（[有赞产品页](https://www.youzan.com/chanpin/mendianjiaoban)）。
- **来源**：www.youzan.com/chanpin/mendianjiaoban。

### 4.5 支付方式

- **为什么需要**：客户付款习惯以微信/支付宝为主，辅以现金、刷卡；门店需要统一的聚合收款与记账口径。
- **常见实现方式**：接入微信支付/支付宝（主扫与被扫），现金与刷卡手工入账；储值余额支付走内部账户；所有支付落统一交易流水。
- **国内同类美业 SaaS 如何做**：行业文章称 2025 年线下商户聚合码覆盖率约 79%（转引自[知乎专栏](https://zhuanlan.zhihu.com/p/2027436189913718788)，原始统计未核实）；微信支付提供扫码支付（付款码）与电子小票的商户接入文档（[微信支付商户文档](https://pay.weixin.qq.com/docs/merchant/products/shopping-receipt/preparation.html)、[扫码支付](https://pay.weixin.qq.com/docs/partner/products/partner-scannedpos-payment/preparation.html)）。
- **来源**：pay.weixin.qq.com 相关文档页；zhuanlan.zhihu.com/p/2027436189913718788。

### 4.6 发票 / 电子小票

- **为什么需要**：消费凭证是客诉与税务的基本依据；纸质小票仍是美业主流，电子化小票/发票是趋势。
- **常见实现方式**：结账后自动/手动打印小票；电子小票可经微信支付商户能力下发；电子发票通常经税务服务商渠道开具（具体接入方式未核实）。
- **国内同类美业 SaaS 如何做**：微信支付官方提供「电子小票」商户接入准备文档（直连商户/服务商两种模式）（[微信支付](https://pay.weixin.qq.com/docs/merchant/products/shopping-receipt/preparation.html)）。
- **来源**：pay.weixin.qq.com/docs/merchant/products/shopping-receipt/preparation.html。

## 五、库存与耗材

### 5.1 出入库

- **为什么需要**：美容院耗材（精华、面膜、精油、一次性用品）单价不高但种类杂、流转快；缺货影响服务，积压过期直接亏损。
- **常见实现方式**：采购入库、领用出库、服务消耗出库、调拨、报损等单据类型；扫码出入库，库存流水按批次记录。
- **国内同类美业 SaaS 如何做**：美盈易称「每款产品贴专属条码，进货、销售、退货一扫搞定，数据自动同步」（[美盈易](https://www.dyysoft.net/product02/1763622011134310.html)，厂商宣传）；美容 SaaS 官网提供进销存/跨店调拨能力（[美容院 SaaS](https://beautysaas.com/cangku.html)）。
- **来源**：www.dyysoft.net/product02/1763622011134310.html；beautysaas.com/cangku.html。

### 5.2 效期预警

- **为什么需要**：面膜、精华、精油均有保质期，部分产品开封后有使用限期；过期即报废，是门店隐形利润流失点。
- **常见实现方式**：入库批次记录生产日期/到期日，定时任务扫描临期批次并推送提醒，联动促销消化临期库存。
- **国内同类美业 SaaS 如何做**：美盈易称「系统自动标记临期产品，提前 30 天、15 天提醒」（[美盈易](https://www.dyysoft.net/product02/1763622011134310.html)，厂商宣传）。
- **来源**：www.dyysoft.net/product02/1763622011134310.html。

### 5.3 盘点

- **为什么需要**：账面库存与实物长期偏离会掩盖损耗与内盗；定期盘点是库存可信度的唯一校准手段。
- **常见实现方式**：按仓库/类目生成盘点单，录入实盘数量自动算盈亏并生成调增/调减单；支持部分盘点（滚动盘点）。
- **国内同类美业 SaaS 如何做**：厂商宣传「一键盘点、跨店调拨、精准统计」（[beautysaas](https://beautysaas.com/cangku.html)）；行业文章强调从「账实不符」走向数字化盘点（[搜狐](https://www.sohu.com/a/958390682_121950194)，厂商软文性质）。
- **来源**：beautysaas.com/cangku.html；www.sohu.com/a/958390682_121950194。

## 六、营销

### 6.1 优惠券

- **为什么需要**：券是最低门槛的到店理由（新客体验券、复购满减券），也是沉睡召回的标准弹药。
- **常见实现方式**：券模板（面额/折扣、适用项目、有效期、领取上限）+ 发放（主动领/定向发/活动发）+ 核销（下单抵扣）+ 状态流水。
- **国内同类美业 SaaS 如何做**：营销型 SaaS 将优惠券列为基础工具，并与积分、老带新组合使用（[企叮咚](https://www.7dingdong.cn/t/%E8%80%81%E5%B8%A6%E6%96%B0%E8%A3%82%E5%8F%98)）。
- **来源**：www.7dingdong.cn（营销工具页）。

### 6.2 拼团

- **为什么需要**：美容服务半径小，拼团借社交关系低成本拉新，把「1 人开团 → 多人参团 → 新客到店」形成闭环。
- **常见实现方式**：小程序拼团活动（成团人数、时限、价格），成团后发券/发订单，到店核销；可限制每时段核销量以平滑到店。
- **国内同类美业 SaaS 如何做**：美盈易称拼团场景下「客户发起 3 人团，系统自动分配预约时段，避免集中到店」，并配合美团、大众点评团购核销防超卖（[美盈易 FAQ](https://www.dyysoft.cn/cqt/1760609141017558.htm)，厂商宣传）；另有行业文章拆解美业拼团裂变逻辑（[新浪](https://cj.sina.com.cn/articles/view/7879923100/1d5ae159c01901hxfe)）。
- **来源**：www.dyysoft.cn/cqt/1760609141017558.htm；cj.sina.com.cn/articles/view/7879923100/1d5ae159c01901hxfe。

### 6.3 老带新（转介绍）

- **为什么需要**：美容院获客成本高，熟客转介绍是信任度最高、成本最低的渠道；没有系统绑定关系，奖励无法兑现。
- **常见实现方式**：老客生成专属海报/邀请码 → 新客注册或首单绑定归属 → 双向奖励（老客得券/返现/积分，新客得体验价）。
- **国内同类美业 SaaS 如何做**：水滴智店宣传「老带新返现」的美业渠道裂变玩法（[搜狐](https://www.sohu.com/a/903223997_122449078)，厂商软文）；朗尊软件描述「老带新双向奖励与 KOC 推荐机制」（[朗尊](https://www.legendshop.cn/saas/member-growth.html)）；亦有文章总结老带新落地误区（[今日头条](https://www.toutiao.com/article/7639678108727132699/)，观点文）。
- **来源**：www.sohu.com/a/903223997_122449078；www.legendshop.cn/saas/member-growth.html；www.toutiao.com/article/7639678108727132699/。

### 6.4 沉睡客召回

- **为什么需要**：美容院客户流失是常态，召回成本远低于拉新；沉睡期越长唤醒难度越大，需要分层策略而非一刀切群发。
- **常见实现方式**：以「最后到店天数」分层（如 30–60 / 60–90 / 90 天以上），分层匹配动作（关怀回访、专属唤醒券、器材或项目升级邀约）；系统定时扫描生成召回任务与触达。
- **国内同类美业 SaaS 如何做**：行业文章给出 30/60/90 天分层运营方法（[搜狐](https://www.sohu.com/a/1089043729_122987883)，运营方法文）；灵依美宣传「沉睡会员客户自动预警」（[灵依美](https://www.lingmasys.cn/)，厂商宣传）；美碧给出召回率 5%→32% 的案例数据（[美碧](https://www.meiruhe.com/news_detail_news-bbfacdd2-fc06-4102-be91-f723414d8ff8.html)，厂商宣传数据，未核实）。
- **来源**：www.sohu.com/a/1089043729_122987883；www.lingmasys.cn；www.meiruhe.com/news_detail_news-bbfacdd2-fc06-4102-be91-f723414d8ff8.html。

### 6.5 短信 / 微信触达

- **为什么需要**：预约提醒、回访、生日、活动通知都依赖触达通道；美容客户主要沉淀在微信生态。
- **常见实现方式**：手机号绑定短信通道（云厂商短信服务）；微信侧通过公众号模板消息或小程序订阅消息推送事件通知（预约成功、核销提醒等）；营销群发需注意频率与合规。
- **国内同类美业 SaaS 如何做**：选型文章把「微信推送通知、回访跟进」列为会员系统核心维度（[CSDN 选型文](https://blog.csdn.net/wencongta/article/details/162424245)，观点文）；具体触达通道组合各家差异大，未核实。
- **来源**：blog.csdn.net/wencongta/article/details/162424245。

## 七、多门店

### 7.1 门店隔离（数据权限）

- **为什么需要**：连锁经营中店长只应看到本店客户、订单与业绩；总部才有全局视图。隔离不清会造成数据外泄与考核失真。
- **常见实现方式**：数据模型带门店维度，按角色授予门店范围的数据权限；总部账号可跨店查询。
- **国内同类美业 SaaS 如何做**：纳客称连锁选型核心关注「数据互通性、管控权限、系统稳定性」（[纳客](https://www.nakesoft.com/hyzx/9864.html)，厂商宣传）。
- **来源**：www.nakesoft.com/hyzx/9864.html。

### 7.2 跨店消费与分账

- **为什么需要**：客户在 A 店办的卡会到 B 店消费（通存通兑是连锁卖点），但业绩与资金必须按门店准确切分，否则门店核算与加盟分成都无法进行。
- **常见实现方式**：会员与卡项总部化管理（跨店可用）；消费流水同时记录「发生门店」与「业绩归属门店」；按可配置分账规则出门店间往来账。
- **国内同类美业 SaaS 如何做**：纳客提供「跨店分账」功能，宣传可灵活配置分账规则适配多元合作模式（[纳客](https://www.nakesoft.com/hyzx/10208.html)，厂商宣传）；傲蓝称多店数据互联共享、总部可对比分析（[傲蓝](https://www.aolan.net/meirong/custompage.aspx?id=46)）。
- **来源**：www.nakesoft.com/hyzx/10208.html；www.aolan.net/meirong/custompage.aspx?id=46。

### 7.3 总部报表

- **为什么需要**：连锁老板需要跨店对比（营收、客流、客单、项目结构）才能做扩张与关停决策；单店报表无法回答「哪家居于什么水平」。
- **常见实现方式**：总部汇总查询/报表模块，按门店、时段、项目、员工多维聚合；异常指标（如连续下滑门店）提醒。
- **国内同类美业 SaaS 如何做**：美务通、美盈易等均设连锁报表/数据分析产品页（[美务通](https://meiwutong.com/sjzn.htm)、[美盈易](https://www.dyysoft.net/sjbb.html)，厂商宣传）。
- **来源**：meiwutong.com/sjzn.htm；www.dyysoft.net/sjbb.html。

## 八、合规与隐私

### 8.1 客户健康信息处理

- **为什么需要**：肤质、过敏史、健康备注属于《个人信息保护法》第二十八条所称敏感个人信息中的「医疗健康」类信息；美容院确需采集（防事故），但必须依法处理。
- **常见实现方式**：单独同意（采集时单独勾选/签署）；最小必要（只存服务必需项）；访问权限收紧（仅服务技师与店长可见）；到期或客户要求时删除。
- **国内同类美业 SaaS 如何做**：公开资料中未见厂商明确宣传「敏感个人信息单独同意」的产品化实现（未核实），多为通用隐私条款；合规要求以法规为准绳。
- **来源**：《中华人民共和国个人信息保护法》全文（[中国人大网](http://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html)）；国家网信办「个人信息保护政策法规问答」（[网信办](https://www.cac.gov.cn/2026-01/09/c_1769688003183197.htm)）。

### 8.2 照片留存（服务前后对比照）

- **为什么需要**：皮肤管理、SPA 等以「效果可见」为卖点，前后对比照既是服务凭证也是复购话术；但人脸照片属于个人信息（如涉生物识别则更敏感），留存与使用需有边界。
- **常见实现方式**：照片按客户档案归档，仅限本人与授权员工查看；使用于营销前取得单独授权；设定留存期限与删除机制。
- **国内同类美业 SaaS 如何做**：公开资料未见系统化的照片留存合规方案（未核实）；建议以 PIPL 告知同意与最小必要原则自行设计。
- **来源**：《个人信息保护法》（[中国人大网](http://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html)）；网信办问答（[网信办](https://www.cac.gov.cn/2026-01/09/c_1769688003183197.htm)）。

### 8.3 个人信息保护基线（告知同意 / 权限 / 日志）

- **为什么需要**：会员手机号、消费记录属于个人信息；美容行业客户与员工纠纷多发，操作留痕与权限最小化既是合规也是自保证据。
- **常见实现方式**：采集前隐私政策与同意记录（谁、何时、同意什么版本）；后台权限按角色最小化；敏感数据访问与导出写审计日志。
- **国内同类美业 SaaS 如何做**：法规问答明确个人信息定义与处理要求（[网信办](https://www.cac.gov.cn/2026-01/09/c_1769688003183197.htm)）；行业系统层面公开披露有限（未核实）。
- **来源**：www.cac.gov.cn/2026-01/09/c_1769688003183197.htm；《个人信息保护法》。

### 8.4 预付卡（储值）合规

- **为什么需要**：美容院属居民服务业，发行单用途商业预付卡（储值卡）受《单用途商业预付卡管理办法（试行）》约束：需向商务主管部门备案，并按比例进行资金存管或提供担保；预收资金管理是行业监管重点。
- **常见实现方式**：系统侧能出具备案所需的发卡与余额报表；记录每张卡的发售与兑付流水，支持主管部门检查口径。
- **国内同类美业 SaaS 如何做**：公开资料未见厂商直接宣传「备案报表」能力（未核实）。
- **来源**：《单用途商业预付卡管理办法（试行）》（[中国政府网](https://www.gov.cn/zhengce/2012-09/21/content_5712346.htm)）；商务部单用途预付卡业务信息管理（[商务部](http://yfk.mofcom.gov.cn/card/)，备案需提供资金存管信息或担保/保险/银行保函）；[百度法律问答：美容院储值需备案](https://ailegal.baidu.com/legalarticle/qadetail?id=e9af120ca6006e250702)。

### 8.5 生活美容与医疗美容边界

- **为什么需要**：监管明确生活美容机构不得开展医疗美容活动；美容院系统若支持录入或营销医美性质项目（注射、光电等）将放大经营法律风险。
- **常见实现方式**：项目库按「生活美容」口径建设；系统不提供医美病历/诊疗功能；营销内容合规校验（不出现医疗效果承诺）为人工流程。
- **国内同类美业 SaaS 如何做**：市场监管总局等部门发布《关于进一步加强医疗美容行业监管工作的指导意见》（[市场监管总局](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/ggjgs/art/2023/art_ab97d5643ddc45ae861e7f351842f512.html)）；地方监管发布美容行业合规指引，提示核查《医疗机构执业许可证》《公共场所卫生许可证》（[泉州市市场监管局](https://scjgj.quanzhou.gov.cn/xxgk/zcjd/202509/t20250901_3205412.htm)）。美业 SaaS 的对应产品化措施未见公开资料（未核实）。
- **来源**：www.samr.gov.cn（指导意见原文页）；scjgj.quanzhou.gov.cn/xxgk/zcjd/202509/t20250901_3205412.htm。

## 九、硬件对接

### 9.1 小程序 / App（客户端与员工端）

- **为什么需要**：客户自助预约、查卡余额、领券都在小程序完成；员工端查看排班与业绩，减少前台传话。
- **常见实现方式**：微信小程序承载 C 端（预约、会员中心、券包），管理后台 + 员工端 App/小程序承载 B 端。
- **国内同类美业 SaaS 如何做**：行业测评称主流预约系统已实现「顾客小程序自助选项目、指定技师和时段，系统自动规避排班冲突，实时同步员工端与前台 POS」（[RateMyPOS](https://ratemypos.com/8280/)，第三方博客）；美盈易宣传多渠道预约（官网、APP、小程序）（[美盈易](https://www.dyysoft.net/hyzx/1752116455291826.html)）。
- **来源**：ratemypos.com/8280/；www.dyysoft.net/hyzx/1752116455291826.html。

### 9.2 收银机 / 收银终端

- **为什么需要**：前台需要一个稳定的多合一操作终端（收银、核销、打票），手机操作在高峰期效率不足。
- **常见实现方式**：Android/Windows 收银一体机运行 SaaS 收银端（Web 或客户端）；扫码枪、钱箱、打印机外设接终端。
- **国内同类美业 SaaS 如何做**：美业收银系统普遍以「收银一体机 + 外设」形态交付（行业测评文综述，如[搜狐实测](https://www.sohu.com/a/1024659312_122717670)，厂商软文性质；具体某厂商硬件细节未核实）。
- **来源**：www.sohu.com/a/1024659312_122717670。

### 9.3 小票打印机

- **为什么需要**：结账小票与预约凭证是行业习惯；云打印让小程序/云端订单自动出票，无需专人操作。
- **常见实现方式**：接云打印服务商（如飞鹅、优声云等）HTTP API，订单事件触发打印；或本地 USB/网口打印机直连收银终端。
- **国内同类美业 SaaS 如何做**：开发者社区有微信小程序对接云打印机（飞鹅）自动出票的完整实践（[腾讯云开发者社区](https://cloud.tencent.com/developer/article/1638082)、[CSDN 优声云方案](https://blog.csdn.net/u010520850/article/details/121053114)）。
- **来源**：cloud.tencent.com/developer/article/1638082；blog.csdn.net/u010520850/article/details/121053114。

### 9.4 扫码（扫码枪 / 付款码支付）

- **为什么需要**：被扫（店员用扫码枪扫客户付款码）是线下最高频收款动作，需与收银单打通自动记账。
- **常见实现方式**：接入微信支付/支付宝「付款码支付（扫码支付）」接口，扫码枪读取付款码后由收银端发起扣款并回流订单状态。
- **国内同类美业 SaaS 如何做**：微信支付官方提供扫码支付（被扫）商户/服务商接入文档（[微信支付](https://pay.weixin.qq.com/docs/partner/products/partner-scannedpos-payment/preparation.html)）；行业文章描述扫码枪 + 聚合支付的通用对接方式（[知乎专栏](https://zhuanlan.zhihu.com/p/2027436189913718788)）。
- **来源**：pay.weixin.qq.com 扫码支付文档；zhuanlan.zhihu.com/p/2027436189913718788。

### 9.5 门禁 / 智能硬件

- **为什么需要**：中大型门店以会员刷卡/扫码/人脸开门、更衣柜电子锁提升体验与安全；对多数小型美容院属可选件。
- **常见实现方式**：未核实——公开资料中未检索到美业 SaaS 与门禁/柜锁对接的通用方案，具体协议与厂商集成方式待进一步调研。
- **国内同类美业 SaaS 如何做**：未核实。
- **来源**：暂无可引用来源。

## 十、建议 MVP 范围（开业必需 vs 可后置）

原则：美容院开业期的生命线是「卡（储值/次卡）+ 预约 + 收银提成」，营销自动化与多门店都可以后置；合规项是底线，不算可选。

### 10.1 开业必需（P0）

| 功能 | 理由 | 与本仓现状的关系（依据 README/todo.md） |
| --- | --- | --- |
| 客户档案 + 标签 + 过敏/禁忌记录 | 服务安全底线，开业第一天就要用 | 已有用户/会员 CRUD，缺过敏与健康字段 |
| 会员等级 + 储值 + 次卡 | 现金流与锁客核心，开业即售卡 | 已有 Member{Level} 与 Member Card Management；需确认本金/赠送分账与核销流水 |
| 积分（简化：消费得分 + 抵扣） | 行业惯例，实现成本低 | 已实现消费积分（1 元 1 分） |
| 服务项目库（含时长） | 预约与收银的地基 | 已有 Service Management 与类目 |
| 技师排班 + 预约（冲突检测 + 改约） | 无冲突检测必有撞单客诉 | 已有 Online Booking；需确认房间/工位维度与冲突检测 |
| 收银（组合支付 + 卡项核销）+ 小票 | 每笔交易都经过这里 | 已有 Finance/订单；需确认多支付方式组合与次卡核销 |
| 提成记录（先固定比例，规则引擎后置） | 美容师薪资争议是最高频内部矛盾 | 已有 Finance Report；提成规则引擎未见，建议 P0 先做简单比例记账 |
| 日结 / 交接班 | 长短款责任划分，开业必需 | 未见实现（未核实） |
| 库存（出入库 + 盘点，手工为主） | 耗材账实要能对上 | 未见实现（未核实） |
| 合规基线：同意记录、权限最小化、审计日志 | PIPL/预付卡监管底线成本极低 | 已有操作审计日志；同意记录缺失 |

### 10.2 可后置（P1 / P2）

| 功能 | 建议时点 | 理由 |
| --- | --- | --- |
| 效期预警自动化 | P1 | 开业期 SKU 少可人工管理；SKU 上规模后自动化收益明显 |
| 耗材关联（项目 BOM 自动扣库） | P1 | 依赖库存模块先稳定 |
| 营销自动化（拼团、老带新、沉睡召回） | P1 | 依赖会员基数；开业期靠基础券与人工回访即可 |
| 短信/微信触达体系化 | P1 | 预约提醒可先人工；渠道申请（小程序订阅消息、短信签名）有周期，宜早启动申请 |
| 发票 / 电子小票 | P1 | 对接外部渠道，非开业阻塞项 |
| 完整提成规则引擎（阶梯/多人分佣） | P1 | 固定比例可支撑开业；团队扩大后再上引擎 |
| 爽约定金 | P1 | 涉及资金与法律条款，先以免费提醒过渡 |
| 多门店（隔离/跨店/总部报表） | P2 | 单店模型稳定后再复制；架构上预留门店字段即可 |
| 收银一体机深度适配、门禁/柜锁 | P2 | 可先以笔记本/平板 + 扫码枪起步；门禁未检索到通用方案（未核实） |

### 10.3 风险提示

- 预付卡备案与资金存管是**业务合规义务**，不是软件功能，但系统应能支撑备案报表口径；正式对外售卡前建议法务确认当地执行口径。
- 肤质/过敏字段一上系统即触发敏感个人信息义务（单独同意、权限收紧），建议与档案功能同批上线，而非事后补。
- 本调研中的厂商数据（召回率、覆盖率、爽约率等）均来自宣传或自媒体，做产品决策时不应直接引用。
